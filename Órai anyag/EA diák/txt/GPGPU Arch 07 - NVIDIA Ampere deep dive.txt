At a glance
●   Ampere was the second generation ray tracing NVIDIA GPU released in 2020
●   It is an umbrella term, as for most NVIDIA GPUs, it encapsulates two distinct
    product lines:
     ○   The first release was the A100 which is a data center GPU
     ○   This was followed by the GA102 and GA104 chips, first introduced with
          ■ GA102: 3080, 3090, A6000 RTX, A40
          ■ GA104: 3070
●   It is based on Samsung’s ‘8nm’ 8N process
In numbers
●   7 GPCs
●   Each GPC contains
     ○   6 TPCs
     ○   1 raster engine
     ○   (NEW) 2 ROP partitions
     ○   (NEW) 8 ROP units per ROP partition
●   Each TPC contains
     ○   2 SMs
     ○   1 polymorph engine
●   Each SM contains
     ○   128 CUDA cores
     ○   4 Texture units
     ○   4 Tensor Cores (3rd gen)
     ○   1 RT Core (2nd gen)
     ○   256 KB register file partitioned into 4 64 KB parts
     ○   128 KB of configurable L1/Shared memory
In numbers
●   12 x 32 bit memory controllers (384 bit)
●   512 KB L2 cache per controller (6144 KB in total)
●   An SM partition can now service 2 FP32 operations per clock (in Turing: it
    could only double issue a float-int operation pair)

SM
●   Re-arranged the two main datapaths:
     ○   1 with 16 FP32 CUDA Cores
     ○   1 with 16 FP32 CUDA Cores and 16 INT32
●   Tricky: each clock, an SM partition can
     ○   either execute 32 FP32 operations
     ○   or execute 16 FP32 and 16 INT32 operations
●   They kept the Turing double-speed FP16 operations (HFMA)
Unified shared memory
●   Graphics mode: 64 KB L1 data/texture cache + 48 KB shared + 16 KB
    reserved for the graphics pipeline operations
●   In compute mode:
                    L1                             Shared

                  128 KB                             0 KB

                  120 KB                             8 KB

                  112 KB                            16 KB

                   96 KB                            32 KB

                   64 KB                            64 KB

                   28 KB                            100 KB
Tensor cores
●   4 per SM
●   256 FP16/32 FMA per clock
●   3rd gen now supports FP16, BF16 (alternative to IEEE FP16), TF32 (‘tensor
    float’), FP64, INT8, INT4, binary (INT1)
     ○   FP16/BF16 has 16x larger throughput in tensor cores than FP32
●   TF32 basically retains the exponent range of FP32 but discards mantissa bits
    beyond what is representable with FP16
●   Faster execution if your input matrices are (lower bound) matches of
    particular sparsity patterns

There are two types of instructions:

●   Fixed latency (coupled)
●   Unknown latency (decoupled)

On Maxwell, fixed latency counting was moved into the compiler while unknown
latencies are handled via barriers.

Control code
●   Instructions are 8 bytes
●   Every couple of lines the compiler injects some execution-related information,
    such as data stall cycles for coupled instructions, etc. called control codes
●   Some parts of it are visible in SASS (like REUSE), some are not
●   For example, Maxwell uses 8 bytes (every 3 lines) to set the properties of the
    subsequent 3 lines
●   The 8 bytes are decomposed into 3x21 bits:


     stall : yield : write barrier : read barrier : wait barrier
